# Issue #99 pilot evidence

Date: 2026-10-24–25. Candidate release: Technitium v15.6.2. The official Docker manifest is `sha256:eb48ac5c135f4ab936b536f74f853d53e15ab39ef37fdbc9598a089b90d9f245` (amd64, arm64, arm/v7). The Pi portable archive passed its published SHA-256 check. The [v15.6.2 changelog](https://github.com/TechnitiumSoftware/DnsServer/blob/v15.6.2/CHANGELOG.md) records cluster sync and UDP receive fixes after the plan's v15.6.1 candidate.

| Public seam | Required behavior | Observed evidence | Status |
| --- | --- | --- | --- |
| `check.sh` | Independent recursion with no household listener | Both fresh Docker instances answered external A queries with no forwarders configured; each answered again while its peer was stopped. Neither published a Host port. | Pass for disposable Linux instances |
| `pi_check.sh` | Native Pi 3 recursion, filtering, and capacity | Pi 3 Model B, Debian 13 ARM64, pinned portable v15.6.2 plus .NET 10.0.13 in an outbound-only user namespace. Cold external A query 1419 ms; 50 sequential queries p95 2.3 ms; 800 cached queries with 8 workers p95 9.2 ms; 800 filtered queries with 8 workers p95 8.8 ms; RSS 122540 KiB. Filtering returned the declared NXDOMAIN response for a previously resolving domain. Password, config, and processes were removed after the run. | Pass for measured short workload; Pi cluster membership and long soak pending |
| `cluster_check.py` | Catalog and filtering sync, relevant ports, secondary expiry | Two Docker nodes joined over bridge-only HTTPS (TCP 53443); DNS TCP 53 accepted connections and DNS UDP 53 answered queries. A catalog member A record and blocked-zone policy reached the secondary. `home` and reverse member zones were provisioned. A 60 second SOA expiry stopped authoritative service after 75 seconds when minimum refresh/retry was set to 10 seconds. With the default 300 second minimum, the secondary still answered after 110 seconds. | Pass for disposable cluster; production timer margin must account for defaults |
| `dhcp_check.py` | Excluded reserved band, dynamic band, one offer source, options, lease A/PTR lifecycle | Reserved and unreserved clients received their expected bands, gateway, two DNS endpoints, and `home`. A raw packet probe saw one OFFER source. Both A/PTR pairs appeared on the primary and, when catalog zones were present, the secondary. Explicit dynamic lease removal and a one minute natural expiry removed A/PTR records. Scope was disabled and removed afterward. | Pass on the Docker bridge; renewal and collision behavior pending |
| `automation_check.py` | Select an automation path; read/diff, dry run, idempotence, update, restore | Collection v1.1.2 source inserts tokens into URL parameters, so it was rejected before use. The narrow Python standard-library API path sends bearer headers. It read live state, made a dry-run plan without mutation, applied once, found an empty second plan, updated an A record, verified a flushed backup ZIP, deleted the zone and a disabled scope, and restored the record, scope, reservation, and exclusion with DHCP disabled. An immediate backup was empty until files flushed. Scope creation by `set` was observed to enable allocation immediately; the pilot disabled it before backup. | Pass for pilot zone/scope restore; production exact-plan and safe disabled staging pending |

All DHCP broadcasts stayed on the Docker bridge. No Host port was published, no Bell setting was changed, and the Pi's LAN namespace had no Technitium listener. The production Host Compose belongs to #103. Issue #99's explicit pilot acceptance checks passed for these measured workloads. Pi cluster membership and a long soak, lease renewal/collision behavior, and a safe staging method around the initial enabled-scope interval remain deployment gates.

The runner rejected an overlapping invocation. A simulated Docker teardown failure returned a nonzero exit, reported a retry command, and retained the recovery password file with mode `0600`; the verification then removed that file.
